# 阶段5: 实际迁移和清理计划

## 🎯 目标
- 将旧模块的业务逻辑迁移到统一模块
- 删除25个旧模块文件
- 从main.py中移除旧路由注册
- 减少端点到420个左右

## 📋 迁移优先级

### 高优先级（立即执行）
1. ✅ unified_analysis.py - 最简单，只有3个旧模块
2. ✅ unified_projects.py - 只有2个旧模块
3. ✅ unified_reports.py - 只有2个旧模块
4. ✅ unified_tools.py - 只有1个旧模块

### 中优先级
5. unified_documents.py - 2个旧模块
6. unified_skills.py - 3个旧模块

### 低优先级（最复杂）
7. unified_chat.py - 5个旧模块
8. unified_rag.py - 5个旧模块
9. unified_knowledge_graph.py - 2个旧模块（但逻辑复杂）

## 🔧 迁移步骤（每个模块）

1. **读取旧模块代码**
   - 提取业务逻辑
   - 识别依赖关系
   - 记录数据库操作

2. **迁移到统一模块**
   - 保持API签名不变
   - 整合业务逻辑
   - 更新导入路径

3. **从main.py移除旧路由**
   - 注释掉旧路由注册
   - 记录移除的路由

4. **删除旧模块文件**
   - 移动到archive目录（备份）
   - 从git中删除

5. **测试验证**
   - 启动应用
   - 验证API可用

## 📊 预期效果

- 删除模块: 25个
- 减少端点: ~470个 (894 → ~420)
- 清理代码: ~15000行
