## 架构设计

### 分层架构

```
应用层
    ↓
混合检索层 (HybridRetriever)
    ↓
缓存层 (LRUCache)
    ↓
抽象层 (VectorStore)
    ↓
后端层 (FAISS / Chroma)
```

### 核心组件

#### 1. 抽象接口层 (`base.py`)

**职责**：定义统一接口

**核心类**：
- `VectorStore`: 抽象基类
- `Document`: 文档数据类
- `SearchResult`: 搜索结果
- `DistanceMetric`: 距离度量枚举
- `IndexType`: 索引类型枚举

**设计模式**：
- 抽象工厂模式
- 模板方法模式
- 策略模式

#### 2. FAISS 后端 (`faiss_store.py`)

**特性**：
- 多种索引：Flat、IVF、HNSW
- 高性能：O(log n) 搜索
- GPU 支持
- 手动持久化

**适用场景**：
- 大规模数据（> 100K）
- 极致性能需求
- GPU 资源可用

#### 3. Chroma 后端 (`chroma_store.py`)

**特性**：
- 自动持久化
- 强大的元数据过滤
- 简单易用
- 内置 HNSW

**适用场景**：
- 中小规模数据（< 100K）
- 快速开发
- 复杂过滤需求

#### 4. 缓存层 (`lru_cache.py`)

**特性**：
- LRU 淘汰策略
- O(1) 操作
- TTL 过期
- 语义缓存（可选）

**性能提升**：
- 命中延迟：< 2μs
- 命中率：20-80%（取决于查询重复度）
- 相比直接搜索：**400-7000倍加速**

#### 5. 混合检索 (`hybrid.py`)

**算法**：
- 密集检索：向量相似度（语义）
- 稀疏检索：BM25（关键词）
- 融合策略：RRF / Linear / Max

**效果提升**：
- 召回率：+10-30%
- 适用范围：更广泛的查询类型

## 关键技术

### 1. 向量检索算法

**FAISS HNSW**：
- 层次化导航图
- 构建：O(n log n)
- 搜索：O(log n)
- 精确度：95-99%

**FAISS IVF**：
- 倒排文件索引
- 聚类加速
- 适合百万级数据

### 2. BM25 算法

```
BM25(q, d) = Σ IDF(qi) * (f(qi, d) * (k1 + 1)) / (f(qi, d) + k1 * (1 - b + b * |d| / avgdl))
```

- 词频饱和
- 长度归一化
- IDF 加权

### 3. RRF 融合

```
RRF(d) = Σ weight / (k + rank(d))
```

- 基于排名
- 不依赖分数尺度
- 鲁棒性强

### 4. 语义缓存

- 余弦相似度匹配
- 阈值可配置（默认 0.95）
- 参数必须完全匹配

```python
# 混合检索 + 缓存
qa_system = DocumentQA(dimension=768)
qa_system.add_documents(documents)
results = qa_system.search(query, query_vec, top_k=5)
```

**优势**：
- 语义理解：向量检索

- 快速响应：缓存

### 场景2：知识图谱检索

```python
# 元数据过滤 + 向量搜索
results = store.search(
    query_embedding,
    top_k=10,
    filters={"entity_type": "Person", "year": {"$gte": 2020}}
)
```

**优势**：
- 结构化过滤
- 语义搜索
- 高效组合

```python
# FAISS HNSW + GPU
store = FaissVectorStore(
    dimension=768,
    index_type=IndexType.HNSW,
    use_gpu=True
)
```

**优势**：
- 百万级数据
- 毫秒级延迟
