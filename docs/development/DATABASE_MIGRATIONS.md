## 概述

FieldMind 使用 **Alembic** 进行数据库迁移管理。Alembic 是 SQLAlchemy 的数据库迁移工具，提供版本控制和自动化模式变更功能。

### 为什么需要数据库迁移？

- ✅ **版本控制**: 跟踪数据库模式的所有变更历史
- ✅ **可重复**: 在不同环境（开发、测试、生产）中一致地应用变更
- ✅ **可回滚**: 安全地撤销错误的变更
- ✅ **协作**: 团队成员同步数据库模式变更
- ✅ **自动化**: 从 SQLAlchemy 模型自动生成迁移脚本

### 项目结构

```
.

│   ├── versions/               # 迁移脚本存储目录

```

## 快速开始

### 新项目初始化

如果是全新的项目（数据库不存在）：

```bash
# 1. 确保环境变量已配置
export DATABASE_URL="sqlite:///./data/fieldmind.db"

# 2. 初始化数据库（应用所有迁移）
python migrate.py init
```

### 已有数据库

如果数据库已存在但没有迁移记录：

```bash
# 标记当前数据库版本（不执行 SQL）
python migrate.py stamp head
```

### 验证安装

```bash
# 查看当前数据库版本
python migrate.py current

# 查看迁移历史
python migrate.py history
```

## 迁移工作流

### 标准开发流程

```
修改模型 → 创建迁移 → 审查迁移 → 应用迁移 → 测试
```

#### 1. 修改 SQLAlchemy 模型

在 `app/models/` 中修改或创建模型：

```python
# app/models/user.py
from sqlalchemy import Column, String, Boolean
from app.database import Base

class User(Base):
    __tablename__ = "users"
    
    id = Column(String(36), primary_key=True)
    email = Column(String(255), unique=True, nullable=False, index=True)
    username = Column(String(50), unique=True, nullable=False, index=True)
    
    # 新增字段
    avatar_url = Column(String(500), nullable=True)  # ← 新增
    bio = Column(Text, nullable=True)                # ← 新增
```

#### 2. 创建迁移

```bash
python migrate.py create "添加用户头像和简介字段"
```

这会在 `alembic/versions/` 中生成一个新的迁移文件：

```
alembic/versions/20260801_1430-abc123def456_添加用户头像和简介字段.py
```

#### 3. 审查迁移脚本

**非常重要！** 自动生成的迁移可能不完美，需要人工审查：

```python
def upgrade() -> None:
    """Upgrade schema."""
    # ### commands auto generated by Alembic - please adjust! ###
    op.add_column('users', sa.Column('avatar_url', sa.String(length=500), nullable=True))
    op.add_column('users', sa.Column('bio', sa.Text(), nullable=True))
    # ### end Alembic commands ###


def downgrade() -> None:
    """Downgrade schema."""
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_column('users', 'bio')
    op.drop_column('users', 'avatar_url')
    # ### end Alembic commands ###
```

检查项：
- ✅ 字段类型正确
- ✅ 约束条件正确（NOT NULL, UNIQUE 等）
- ✅ 默认值合理
- ✅ downgrade() 能正确回滚

#### 4. 应用迁移

```bash
python migrate.py upgrade
```

#### 5. 测试验证

```bash
# 运行测试
python -m pytest tests/

# 或手动验证
python -c "from app.database import engine; from sqlalchemy import inspect; print(inspect(engine).get_columns('users'))"
```

## 命令参考

### migrate.py 命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `init` | 初始化数据库到最新版本 | `python migrate.py init` |
| `create <消息>` | 创建新迁移（自动检测变更） | `python migrate.py create "添加字段"` |
| `upgrade [版本]` | 升级到指定版本 | `python migrate.py upgrade` |
| `downgrade [版本]` | 降级到指定版本 | `python migrate.py downgrade -1` |
| `current` | 显示当前数据库版本 | `python migrate.py current` |
| `history` | 显示迁移历史 | `python migrate.py history` |
| `stamp <版本>` | 标记版本（不执行 SQL） | `python migrate.py stamp head` |
| `show <版本>` | 显示迁移详情 | `python migrate.py show 2ab6739c7fec` |
| `help` | 显示帮助信息 | `python migrate.py help` |

### Alembic 原生命令

如果需要更高级的功能，可以直接使用 Alembic：

```bash
# 查看当前版本
alembic current

# 创建空白迁移（手动编写 SQL）
alembic revision -m "手动迁移"

# 升级到特定版本
alembic upgrade 2ab6739c7fec

# 降级到特定版本
alembic downgrade 2ab6739c7fec

# 查看 SQL 但不执行
alembic upgrade head --sql

# 查看迁移链
alembic history --verbose
```

## 最佳实践

### 1. 迁移消息命名

使用清晰、描述性的消息：

✅ **好的示例**:
```bash
python migrate.py create "添加用户头像字段"
python migrate.py create "修改文档状态枚举值"
python migrate.py create "为项目表添加owner_id外键"
```

❌ **不好的示例**:
```bash
python migrate.py create "更新"
python migrate.py create "修复"
python migrate.py create "test"
```

### 2. 一次迁移做一件事

每个迁移应该专注于单一的变更：

✅ 一个迁移：添加 `avatar_url` 字段  
✅ 另一个迁移：修改 `status` 枚举  

❌ 一个迁移同时做十件事

### 3. 总是审查自动生成的迁移

Alembic 的自动检测不是 100% 准确，可能遗漏：
- 索引变更
- CHECK 约束
- 自定义类型
- 数据迁移

### 4. 处理数据迁移

当需要迁移数据时，在 `upgrade()` 中添加自定义代码：

```python
def upgrade() -> None:
    # 添加新字段（允许 NULL）
    op.add_column('users', sa.Column('full_name', sa.String(100), nullable=True))
    
    # 数据迁移：从 username 复制到 full_name
    connection = op.get_bind()
    connection.execute(
        sa.text("UPDATE users SET full_name = username WHERE full_name IS NULL")
    )
    
    # 修改为 NOT NULL
    op.alter_column('users', 'full_name', nullable=False)


def downgrade() -> None:
    op.drop_column('users', 'full_name')
```

### 5. 测试迁移的双向性

确保 upgrade 和 downgrade 都能正常工作：

```bash
# 升级
python migrate.py upgrade

# 测试功能...

# 降级
python migrate.py downgrade -1

# 再次升级
python migrate.py upgrade
```

### 6. 生产环境迁移

在生产环境应用迁移时：

```bash
# 1. 备份数据库
pg_dump fieldmind_db > backup_$(date +%Y%m%d_%H%M%S).sql

# 2. 预览将执行的 SQL（可选）
alembic upgrade head --sql > migration.sql
# 审查 migration.sql

# 3. 应用迁移
python migrate.py upgrade

# 4. 验证
python migrate.py current
```

### 7. 版本控制

✅ **提交到 Git**:
- `alembic/versions/*.py` - 所有迁移脚本
- `alembic.ini` - Alembic 配置
- `migrate.py` - 迁移管理脚本

❌ **不要提交**:
- `data/fieldmind.db` - 开发数据库
- `*.pyc` - 编译后的 Python 文件

## 常见场景

### 场景 1: 添加新字段

```bash
# 1. 修改模型
# app/models/project.py
class Project(Base):
    # ...
    tags = Column(JSON, nullable=True)  # ← 新增

# 2. 创建迁移
python migrate.py create "为项目表添加tags字段"

# 3. 应用迁移
python migrate.py upgrade
```

### 场景 2: 修改字段类型

```python
# 修改前：title = Column(String(200))
# 修改后：title = Column(String(500))

# 创建迁移
python migrate.py create "扩展文档标题长度"

# 审查生成的迁移
def upgrade():
    op.alter_column('documents', 'title',
                    existing_type=sa.String(length=200),
                    type_=sa.String(length=500))
```

### 场景 3: 添加外键关系

```python
# app/models/document.py
class Document(Base):
    # ...
    project_id = Column(Integer, ForeignKey('projects.id'), nullable=True)
    project = relationship("Project", back_populates="documents")

# 创建迁移
python migrate.py create "为文档添加项目关联"
```

### 场景 4: 重命名字段

```python
# 手动创建迁移并编辑
python migrate.py create "重命名doc_metadata为metadata"

# 编辑生成的迁移文件
def upgrade():
    op.alter_column('documents', 'doc_metadata', new_column_name='metadata')

def downgrade():
    op.alter_column('documents', 'metadata', new_column_name='doc_metadata')
```

### 场景 5: 添加索引

```python
# app/models/document.py
class Document(Base):
    # ...
    status = Column(Enum(ProcessStatus), index=True)  # ← 添加索引

# 创建迁移
python migrate.py create "为文档状态添加索引"
```

### 场景 6: 删除表（危险操作）

```bash
# 1. 从模型中移除类定义

# 2. 创建迁移
python migrate.py create "删除旧的legacy_data表"

# 3. 审查迁移（确保downgrade能恢复）
def upgrade():
    op.drop_table('legacy_data')

def downgrade():
    # 重新创建表结构
    op.create_table('legacy_data', ...)
```

### 场景 7: 回滚错误的迁移

```bash
# 发现最新的迁移有问题

# 1. 回退一步
python migrate.py downgrade -1

# 2. 删除错误的迁移文件
rm alembic/versions/20260801_xxxx-错误的迁移.py

# 3. 修复模型并重新创建迁移
python migrate.py create "正确的迁移描述"

# 4. 应用新迁移
python migrate.py upgrade
```

## 故障排除

### 问题 1: "Target database is not up to date"

**原因**: 数据库版本与迁移脚本不同步

**解决**:
```bash
# 查看当前版本
python migrate.py current

# 查看迁移历史
python migrate.py history

# 升级到最新
python migrate.py upgrade head
```

### 问题 2: "Can't locate revision identified by 'xxxx'"

**原因**: 迁移文件被删除或损坏

**解决**:
```bash
# 方案1: 从 Git 恢复迁移文件
git checkout alembic/versions/

# 方案2: 重新标记版本（谨慎使用）
python migrate.py stamp head
```

### 问题 3: Alembic 没有检测到模型变更

**原因**: 
- 模型未在 `alembic/env.py` 中导入
- Base.metadata 未正确配置

**解决**:
```python
# 检查 alembic/env.py
from app.models import user, project, document  # 确保所有模型被导入
target_metadata = Base.metadata  # 确保此行存在
```

### 问题 4: 迁移时数据丢失

**预防措施**:
```bash
# 1. 总是先备份
cp data/fieldmind.db data/fieldmind.db.backup

# 2. 使用事务（SQLite 自动）
# 3. 测试 downgrade 是否能回滚
python migrate.py downgrade -1
python migrate.py upgrade
```

### 问题 5: 冲突的迁移

**场景**: 多个开发者同时创建迁移

**解决**:
```bash
# 1. 拉取最新代码
git pull

# 2. 查看迁移历史
python migrate.py history

# 3. 如果有分叉，手动合并
alembic merge -m "合并迁移分支" <rev1> <rev2>
```

### 问题 6: 无法连接数据库

**检查项**:
```bash
# 1. 检查 DATABASE_URL 环境变量
echo $DATABASE_URL

# 2. 检查 .env 文件
cat .env | grep DATABASE_URL

# 3. 测试数据库连接
python -c "from app.database import engine; engine.connect()"
```

## 技术细节

### Alembic 版本表

Alembic 在数据库中创建 `alembic_version` 表来跟踪当前版本：

```sql
SELECT * FROM alembic_version;
-- version_num
-- 2ab6739c7fec
```

### 迁移文件命名

格式: `{timestamp}-{revision}_{slug}.py`

例子: `20260801_1228-2ab6739c7fec_initial_schema.py`

- `20260801_1228`: 时间戳（年月日_时分）
- `2ab6739c7fec`: 唯一修订ID
- `initial_schema`: 人类可读的描述

### 迁移链

迁移通过 `down_revision` 链接：

```python
# 第一个迁移
revision = '2ab6739c7fec'
down_revision = None  # 没有前置迁移

# 第二个迁移
revision = 'abc123def456'
down_revision = '2ab6739c7fec'  # 指向上一个迁移
```

### 环境配置

`alembic/env.py` 中的关键配置：

```python
# 导入所有模型（确保 autogenerate 能检测）
from app.models import user, project, document, entity, context, dialogue, skill

# 设置 metadata（必需）
from app.database import Base
target_metadata = Base.metadata

# 从环境变量读取数据库URL
database_url = os.getenv("DATABASE_URL", "sqlite:///./data/fieldmind.db")
config.set_main_option("sqlalchemy.url", database_url)
```

### SQLite 限制

SQLite 不支持某些 ALTER TABLE 操作：

❌ 不支持:
- 删除列 (DROP COLUMN)
- 修改列 (ALTER COLUMN 大部分操作)
- 添加外键约束到现有表

✅ 支持:
- 添加列 (ADD COLUMN)
- 重命名表 (RENAME TABLE)
- 创建索引 (CREATE INDEX)

**解决方案**: 使用批处理模式

```python
# alembic/env.py
context.configure(
    # ...
    render_as_batch=True  # 启用批处理模式
)
```

### PostgreSQL 迁移

切换到 PostgreSQL 后的优势：

```python
# .env
DATABASE_URL=postgresql://user:password@localhost:5432/fieldmind

# PostgreSQL 支持更多 DDL 操作
def upgrade():
    # 删除列（PostgreSQL 支持）
    op.drop_column('users', 'old_field')
    
    # 添加检查约束
    op.create_check_constraint(
        "check_age_positive",
        "users",
        "age > 0"
    )
    
    # 并发索引创建
    op.create_index(
        'ix_users_email',
        'users',
        ['email'],
        postgresql_concurrently=True
    )
```
