# 数据边界设计文档 - 探讨稿

## 🎯 核心问题

### 问题1: 什么程度的数据可以进入"干净数据"阶段？
**当前现状**: 标准太简单
```python
# 现在的标准（太宽松）
- 有 text_content ✅
- 字数 ≥ 10 ✅
- 文件类型支持 ✅
→ 就算"干净数据"
```

**问题所在**:
- ❌ 没有内容质量检查（乱码、无意义文本也能通过）
- ❌ 没有结构完整性检查（标题、段落、逻辑）
- ❌ 没有语义可理解性检查（是否能提取知识）
- ❌ 没有元数据完整性检查（时间、来源、作者）

---

### 问题2: 什么样的数据才算"处理好"，可以给下游使用？
**当前现状**: 没有明确标准

```
九步流水线执行完 → 就算"处理好" ？
```

**问题所在**:
- ❌ 没有知识提取质量标准（提取了多少实体/事件？）
- ❌ 没有关系完整性标准（实体之间有多少连接？）
- ❌ 没有可用性标准（能否支撑知识图谱/看板？）
- ❌ 没有准确性标准（提取的知识准确吗？）

---

## 📋 我们需要讨论的边界点

### 边界1: 脏数据 → 干净数据（进入九步流水线前）

#### 当前标准（太简单）：
```python
class CleanDataContract:
    REQUIRED_FIELDS = ["document_id", "text_content", "word_count", ...]
    MIN_WORD_COUNT = 10  # 只要10个字就行？
```

#### 我们应该考虑的标准：

**A. 基础质量（必须）**
- [ ] 文本长度：至少多少字？（50字？100字？500字？）
- [ ] 字符质量：乱码占比 <X%？
- [ ] 语言检测：是否可识别语言？
- [ ] 编码正确：UTF-8无损？

**B. 结构完整性（建议）**
- [ ] 有明确的段落分隔？
- [ ] 有标题/章节结构？
- [ ] 句子完整（有句号、问号等）？
- [ ] 不是纯列表/纯表格？

**C. 语义可理解性（建议）**
- [ ] 能提取出至少X个名词？
- [ ] 能识别出基本的主谓宾结构？
- [ ] 不是纯符号/数字？
- [ ] 有实际语义（不是乱码）？

**D. 元数据完整性（必须）**
- [ ] 有文档来源（source_level）？
- [ ] 有时间信息（文档日期或上传日期）？
- [ ] 有基本分类（文档类型）？

**问题**: 你认为哪些是**必须的**？哪些是**建议的**？

### 边界2: 干净数据 → 富化数据（九步流水线处理后）

#### 当前标准（没有）：
```python
# 现在：只要九步执行完就行，不管质量
pipeline.run(document_id)  # 成功 → 就算"处理好"？
```

#### 我们应该考虑的标准：

**A. 知识提取质量（核心）**
- [ ] 至少提取了X个实体？（X = 3? 5? 10?）
- [ ] 至少提取了Y个事件？（Y = 1? 3? 5?）
- [ ] 至少发现了Z个关系？（Z = 2? 5? 10?）
- [ ] 实体类型多样性（不能全是"人物"，要有地点、组织等）？

**B. 知识图谱可用性（核心）**
- [ ] 至少创建了N个知识图谱节点？
- [ ] 至少创建了M条知识图谱边？
- [ ] 节点之间有连接（不是孤立的）？
- [ ] 能形成至少1个知识子图？

**C. 关系完整性（建议）**
- [ ] 实体-实体关系占比 >X%？
- [ ] 实体-事件关系占比 >Y%？
- [ ] 有时间关系（事件顺序）？
- [ ] 有因果关系？

**D. 下游可用性（核心）**
- [ ] 能生成缩影（一句话摘要不为空）？
- [ ] 能支撑看板（有统计数据）？
- [ ] 能支撑知识图谱可视化（有节点和边）？
- [ ] 能支撑检索（有向量化）？

**问题**: 你认为什么程度才算"处理好"？最低标准是什么？

## 💡 我的初步建议（供讨论）

### 边界1: 脏数据 → 干净数据

**最低标准（MUST）**:
```python
class CleanDataContract:
    # 1. 基础质量
    MIN_WORD_COUNT = 50  # 至少50字（而不是10字）
    MAX_INVALID_CHAR_RATIO = 0.1  # 乱码占比 <10%
    
    # 2. 语义可理解性
    MIN_NOUN_COUNT = 3  # 至少能提取3个名词
    MIN_SENTENCE_COUNT = 2  # 至少2句话
    
    # 3. 元数据完整性
    REQUIRED_METADATA = [
        "source_level",  # 必须知道来源层级
        "document_date",  # 必须有日期
        "file_type"      # 必须知道类型
    ]
    
    # 4. 结构完整性（可选，根据文档类型）
    PREFERRED_STRUCTURE = {
        "has_paragraphs": True,   # 建议有段落
        "has_punctuation": True,  # 建议有标点
    }
```

**验证流程**:
```
上传文档
  ↓
提取文本 (IngestionAgent)
  ↓
[检查点1] 基础质量检查
  - 字数 ≥ 50？
  - 乱码率 <10%？
  ↓ 不通过 → 拒绝，返回"文档质量不足"
  ↓ 通过
[检查点2] 语义可理解性检查
  - 能提取名词？
  - 有完整句子？
  ↓ 不通过 → 标记"语义质量低"，但允许继续
  ↓ 通过
[检查点3] 元数据完整性检查
  - 有来源？
  - 有日期？
  ↓ 不通过 → 补充默认值，标记"元数据不完整"
  ↓ 通过
→ 标记为"干净数据"，进入九步流水线
```

### 边界2: 干净数据 → 富化数据

**最低标准（MUST）**:
```python
class EnrichedDataContract:
    # 1. 知识提取质量
    MIN_ENTITY_COUNT = 3      # 至少3个实体
    MIN_EVENT_COUNT = 1       # 至少1个事件
    MIN_RELATIONSHIP_COUNT = 2 # 至少2个关系
    
    # 2. 知识图谱可用性
    MIN_KG_NODE_COUNT = 5     # 至少5个KG节点
    MIN_KG_EDGE_COUNT = 3     # 至少3条KG边
    MIN_CONNECTED_RATIO = 0.5  # 至少50%的节点有连接
    
    # 3. 下游可用性
    MUST_HAVE = [
        "summary",           # 必须有缩影
        "kg_nodes",          # 必须有KG节点
        "kg_edges",          # 必须有KG边
    ]
    
    # 4. 数据连接率
    MIN_CONNECTIVITY_RATE = 0.7  # 数据连接率 ≥ 70%
```

**验证流程**:
```
九步流水线执行完
  ↓
[检查点1] 知识提取质量
  - 实体数 ≥ 3？
  - 事件数 ≥ 1？
  - 关系数 ≥ 2？
  ↓ 不通过 → 标记"知识提取不足"
  ↓ 通过
[检查点2] 知识图谱可用性
  - KG节点 ≥ 5？
  - KG边 ≥ 3？
  - 连接率 ≥ 50%？
  ↓ 不通过 → 标记"知识图谱质量低"
  ↓ 通过
[检查点3] 下游可用性
  - 能生成缩影？
  - 能支撑可视化？
  ↓ 不通过 → 标记"不可用于下游"
  ↓ 通过
[检查点4] 数据连接率
  - 连接率 ≥ 70%？
  ↓ 不通过 → 标记"连接率低"
  ↓ 通过
→ 标记为"富化数据"，可用于知识图谱/看板/检索
```
