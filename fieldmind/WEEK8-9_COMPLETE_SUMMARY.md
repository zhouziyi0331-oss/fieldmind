## 三、Day 2-3: 统一 API 层设计

### 1. 设计原则

#### RESTful 标准
- **资源命名**: 复数名词 (`/users`, `/documents`)
- **HTTP 方法**: 标准语义（GET/POST/PUT/PATCH/DELETE）
- **URL 结构**: `/api/v1/resources/{id}`
- **幂等性**: PUT/DELETE 保证幂等

#### 统一响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {...},
  "meta": {
    "page": 1,
    "page_size": 20,
    "total": 100
  }
}
```

#### 错误处理
```json
{
  "code": 400,
  "message": "Bad Request",
  "errors": [
    {
      "field": "email",
      "message": "Invalid email format"
    }
  ]
}
```

### 2. 设计结果

| 指标 | 数值 |
|------|------|
| **统一后资源数** | 696 |
| **统一后端点数** | 1,577 |
| **标准端点/资源** | ~2.3 |

> **注意**: 统一后端点数 1,577 > 原始 1,189，因为为每个资源补全了标准 CRUD 端点

### 3. 标准端点设计

每个资源的标准端点:

| 方法 | 路径 | 操作 | 说明 |
|------|------|------|------|
| GET | `/api/v1/{resources}` | list | 获取列表（分页、筛选、排序） |
| POST | `/api/v1/{resources}` | create | 创建新资源 |
| GET | `/api/v1/{resources}/{id}` | get | 获取单个资源详情 |
| PUT | `/api/v1/{resources}/{id}` | update | 完整更新 |
| PATCH | `/api/v1/{resources}/{id}` | partial_update | 部分更新 |
| DELETE | `/api/v1/{resources}/{id}` | delete | 删除资源 |

### 4. 限流策略

| 端点类型 | 限流 | 说明 |
|---------|------|------|
| GET (查询) | 200/分钟 | 读操作较宽松 |
| POST/PUT/DELETE | 50/分钟 | 写操作较严格 |
| 默认 | 100/分钟 | 未分类端点 |
